# نقشهٔ هزار مشعل

**بوم تحول آرایش نیروهای مجاهد تبیین** — سامانهٔ ستاد برای مدیران تبلیغات اسلامی شهرستان‌ها.

- **سایت مدیر شهرستان** (`/`): مدیر با شمارهٔ همراه و رمزی که ستاد می‌دهد وارد می‌شود و این قدم‌ها را طی می‌کند:
  1. **چرا:** طرح بحث هزار مشعل و ده درصد کنشگر.
  2. **شکاف:** نیروهای شهرستان و عددهایشان. شکاف در سه جزء دیده می‌شود: کنشگران منتظر دعوت، کنشگران تازهٔ لازم، و مخاطبان بی‌پوشش.
  3. **شش حرکت:** یعنی تحول در آرایش نیروها.
  4. **طرح تحول:** شامل هزینه، آزمون «تحول یا برنامه» و سنجش طرح.
  5. **اجرا:** برنامهٔ اجرا و نقشهٔ راه دو ساله با آهنگ هر سه ماه یک طرح.
  
  پاسخ‌ها روی همان سه برگهٔ بوم دیده و چاپ می‌شوند، و بازخورد دستیار حرف نو همان‌جا می‌رسد.
- **داشبورد ستاد** (`/admin/`): این بخش‌ها را دارد:
  - وضعیت همهٔ شهرستان‌ها و شاخص‌های کل؛
  - ساختن مدیران و رمزها، تکی یا گروهی از اکسل؛
  - دیدن بوم هر شهرستان؛
  - بستهٔ تحلیل برای Claude؛
  - واردکردن، بازبینی و انتشار بازخورد برای هر مدیر.
- **داشبورد مدیرکل** (همان `/admin/`، فقط دیدن): مدیرکل با شمارهٔ همراه وارد می‌شود و وضعیت شهرستان‌ها، شاخص‌ها و بوم کامل هر شهرستان را با بازخورد منتشرشده می‌بیند. پیش‌نویس بازخوردها، رمزها و فهرست مدیران را نمی‌بیند و هیچ چیزی را نمی‌تواند تغییر دهد؛ این محدودیت روی سرور اعمال می‌شود، نه فقط در ظاهر داشبورد.

## ساختار

```
server/            سرور Node بدون وابستگی (http، فایل JSON، نشست، API)
  index.js         نقطهٔ شروع
  app.js           مسیرهای API و فایل‌های ایستا
  store.js         پایگاه دادهٔ فایلی با نوشتن اتمی و پشتیبان ساعتی/روزانه
  auth.js          رمز (scrypt)، نشست، محدودیت تلاش ورود
  analysis.js      بستهٔ تحلیل، دستورالعمل Claude، دریافت و پاک‌سازی بازخورد
  cli.js           ساختن حساب ستاد، افزودن/ورود گروهی مدیران، رمز تازه
public/form/       سایت مدیر شهرستان (یک فایل HTML)
public/admin/      داشبورد ستاد (یک فایل HTML)
public/shared/     فونت راوق، نگاره‌ها، لوگو، و metrics.js (محاسبات مشترک)
test/              آزمون‌های واحد و یکپارچه (node:test)
deploy/            systemd، nginx، نمونهٔ CSV مدیران
docs/DEPLOY.md     راهنمای کامل استقرار
```

## روال کار ستاد

1. **تعریف مدیران:** در «مدیران و رمزها» مدیران را بسازید و متن پیام رمز (شامل نشانی، شماره و رمز موقت) را برای هر مدیر بفرستید. مدیر در اولین ورود تشویق می‌شود رمز را عوض کند.
2. **استان‌های دیگر:** سامانه چنداستانی است. برای هر شهرستان، استانش را در فرم یا در ستون «استان» فایل CSV بنویسید. وقتی بیش از یک استان باشد، بالای همهٔ زبانه‌ها انتخابگر استان و در «شهرستان‌ها» جدول خلاصهٔ استان‌ها می‌آید. شاخص‌ها، فهرست‌ها، اکسل و بستهٔ تحلیل همه به تفکیک استان انتخاب‌شده‌اند. نام استان یکسان می‌شود: «استان اصفهان»، «خراسان‌رضوی» و «ي/ك» عربی هر کدام به یک نام می‌رسند.
3. **دسترسی مدیرکل:** پایین همان بخش «مدیران و رمزها»، در «حساب‌های مدیرکل» نام، شمارهٔ همراه و استان را بنویسید و متن پیام را برایش بفرستید. مدیرکل هر استان فقط شهرستان‌های همان استان را می‌بیند؛ اگر استان خالی بماند، همهٔ استان‌ها را می‌بیند.
4. **پیگیری:** در «شهرستان‌ها» پیشرفت، وضعیت ارسال و عددهای شکاف را ببینید. دکمهٔ «بوم» نسخهٔ فقط‌خواندنی بوم هر شهرستان را باز می‌کند.
5. **تحلیل و بازخورد:**
   1. در زبانهٔ «تحلیل و بازخورد»، «بوم‌های ارسال‌شده» را دانلود کنید. اگر استانی انتخاب شده باشد، فقط بوم‌های همان استان می‌آید. اگر بیش از ۱۰ شهرستان باشد، بسته‌های ۱۰تایی هم پیشنهاد می‌شود تا پاسخ هوش مصنوعی نیمه‌کاره نماند.
   2. فایل را در یک گفت‌وگوی تازه به هر هوش مصنوعی بدهید (Claude یا Gemini یا ChatGPT) و جملهٔ آماده را بنویسید: «طبق دستورالعمل داخل این فایل (بخش instructions)، بوم هر شهرستان را تحلیل کن و فقط آرایهٔ JSON خروجی را بده.» دستورالعمل، شمار شهرستان‌ها و قالب خروجی داخل خود فایل است.
   3. پاسخ را همان‌طور که هست در بخش ۲ جای‌گذاری کنید. متن اضافه، بلوک‌های ``` و پاسخ چند بسته با هم مشکلی ندارد؛ امتیازهایی مثل «7/10» یا «۷» هم خوانده می‌شود. هر بازخورد با شناسهٔ مدیر، یا اگر نبود با نام شهرستان، به مدیرش وصل می‌شود.
   4. بازخوردها پیش‌نویس‌اند. هر کدام را در بخش ۳ بازبینی و در صورت نیاز ویرایش کنید و «انتشار» را بزنید. مدیر آن را در بخش «بازخورد» سایت خودش می‌بیند.

## API

API مدیر شهرستان (کوکی `hn_sid`):

| روش | مسیر | کار |
|---|---|---|
| GET | `/api/me` | کاربر، داده، `rev`، بازخورد منتشرشده (۴۰۱ یعنی وارد نشده) |
| POST | `/api/login` | `{phone, password}` |
| PUT | `/api/form` | `{data, rev, force?}`؛ اگر نسخه جای دیگری عوض شده باشد ۴۰۹ |
| POST | `/api/form/submit` | ارسال بوم‌ها |
| POST | `/api/password` | `{current, next}` |
| POST | `/api/logout` | خروج |

API ستاد (کوکی `hn_admin`) زیر `/api/admin/` است:

| مسیر | کار |
|---|---|
| `login`، `me`، `password` | ورود، اطلاعات کاربر، تغییر رمز |
| `users` | فهرست مدیران با شاخص‌ها (GET)، ساختن (POST) |
| `users/import` | ورود گروهی |
| `users/:id` | ویرایش و فعال/غیرفعال (PATCH) |
| `users/:id/reset-password` | رمز تازه |
| `users/:id/form` | بوم یک شهرستان |
| `users/:id/feedback` | ذخیرهٔ پیش‌نویس (PUT) |
| `users/:id/feedback/publish` و `.../unpublish` | انتشار و برداشتن از انتشار |
| `users/:id/analyze` | تحلیل خودکار، فقط با کلید Claude |
| `export` | بستهٔ تحلیل؛ `?submitted=1`، `?province=…`، `?size=10&part=2` |
| `feedback/import` | واردکردن خروجی Claude |
| `audit` | گزارش رویدادها |
| `viewers` | حساب‌های مدیرکل: فهرست (GET)، ساختن (POST) |
| `viewers/:id` و `viewers/:id/reset-password` | فعال/غیرفعال و ویرایش (PATCH)، رمز تازه |

حساب مدیرکل همان کوکی `hn_admin` را می‌گیرد، اما فقط `me`، `password`، `logout`، `GET users` و `GET users/:id/form` برایش باز است؛ هر درخواست دیگر ۴۰۳ می‌گیرد.

## نکته برای توسعه

- **هم‌گامی محاسبات:** منطق محاسبه در `public/form/index.html` و `public/shared/metrics.js` تکرار شده است. اگر یکی را عوض کردید، دیگری را هم عوض کنید.
- **آزمون هم‌خوانی:** `test/metrics.test.js` با عددهایی که سایت مدیر برای یک نمونه‌داده نشان می‌دهد، هم‌خوانی را می‌سنجد.
